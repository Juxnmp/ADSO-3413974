Dolores del Mercado

3 Problemas Críticos

01
Inventario Fantasma

"El producto estaba en el cuaderno, pero no estaba en la estantería."

  • El 73% de los tenderos bogotanos lleva inventario solo en papel o de memoria (DANE, 2023)
  • Genera desabastecimiento frecuente de alta rotación: arroz, aceite, gaseosas
  • El cliente se va a la tienda de al lado y no vuelve
✅ Solución TiendApp
  • Inventario en tiempo real con actualización automática por cada venta registrada
  • Alerta automática cuando un producto baja del umbral mínimo definido por el tendero
02
Ceguera Financiera Diaria

"Vendí mucho hoy… pero no sé si gané o perdí."

  • La mayoría no distingue entre ingresos brutos y ganancia neta
  • No conocen sus productos más rentables vs. los que ocupan espacio sin retorno
  • Sin datos históricos no pueden negociar mejores precios con proveedores
✅ Solución TiendApp
  • Reporte de cierre diario automático: ventas totales, productos estrella y margen estimado
  • Gráfico semanal de tendencias con lenguaje visual simple, sin tecnicismos financieros
03
Dependencia Total del Dueño

"Si yo no estoy, el negocio no funciona bien."

  • El conocimiento del negocio vive únicamente en la cabeza del propietario
  • Cuando un empleado atiende, los errores en cobros y registros aumentan
  • No existe trazabilidad de lo que pasó cuando el dueño no estaba
✅ Solución TiendApp
  • Roles de usuario: dueño con acceso total, empleado con acceso limitado a ventas
  • Historial de movimientos consultable desde cualquier dispositivo en cualquier momento
02 — Factibilidad Técnica

Stack Tecnológico

📱 Frontend Móvil
React Native + Expo
Una sola base de código para Android e iOS. Actualizaciones OTA sin pasar por tiendas.
🌐 Frontend Web
React.js + Tailwind
Panel de administración ligero para acceso desde PC. Reutiliza componentes del móvil.
⚙️ Backend / BaaS
Firebase
Sin servidor que mantener. Escala automáticamente. Generous free tier para MVP.
💾 Offline / Sync
WatermelonDB
Base de datos local en el dispositivo. Sincroniza cuando hay internet. Crítico para zonas con señal débil.
📸 Escáner
Vision Camera + ML Kit
Escaneo de códigos de barras en tiempo real usando la cámara. Sin hardware adicional.
📊 Reportes
Victory Native / Recharts
Gráficos nativos ligeros optimizados para móvil con soporte offline.
🔔 Notificaciones
Firebase Cloud Messaging
Alertas push gratuitas para stock bajo, recordatorios de cierre y más.
🚀 Deploy / CI-CD
GitHub Actions + EAS
Pipeline automatizado. Una rama main = nueva versión lista en horas.


Módulos Core del MVP

4 Módulos Esenciales

📦
Módulo 1: Inventario
  • CRUD de productos con foto, nombre, precio costo y precio venta
  • Categorías personalizables (bebidas, aseo, granos, etc.)
  • Escáner de código de barras para agregar/buscar productos
  • Campo de cantidad actual y cantidad mínima de alerta
  • Búsqueda por nombre o código
🔔
Módulo 2: Alertas Inteligentes
  • Notificación push cuando stock < mínimo definido
  • Resumen diario automático a la hora de cierre
  • Alerta de productos sin movimiento por X días
  • Recordatorio semanal de conteo de inventario
💰
Módulo 3: Registro de Ventas
  • Registro rápido de venta por unidades (sin POS complejo)
  • Descuento automático del inventario al vender
  • Historial de ventas del día, semana y mes
  • Cálculo automático de margen por producto
  • Modo sin internet: guarda local y sincroniza después
📊
Módulo 4: Reportes Visuales
  • Reporte de cierre diario con totales y top 5 productos
  • Gráfico de ventas semanal (barras simples)
  • Lista de productos con stock crítico
  • Exportar resumen a PDF o imagen para compartir por WhatsApp


Seguridad y Resiliencia

Estrategia de 4 Capas Offline

Capa 1
Almacenamiento Local
WatermelonDB como base de datos local. La app funciona 100% offline: vender, agregar productos y ver reportes sin internet.
Capa 2
Sincronización Inteligente
Cuando detecta WiFi o datos, sincroniza cambios con Firestore. Resolución de conflictos automática: la operación más reciente tiene prioridad.
Capa 3
Respaldo en la Nube
Firestore replica automáticamente en múltiples centros de Google. Backup diario automatizado, retención de 30 días.
Capa 4
Exportación Manual
El tendero puede exportar su inventario completo a Excel con un solo botón. "Guardar copia de mis datos" siempre visible.
📱
Autenticación con número de celular (OTP via SMS) — sin necesidad de recordar contraseñas
🔒
Datos cifrados en tránsito (TLS 1.3) y en reposo (AES-256 en Firebase)
👤
Cada tendero solo puede ver sus propios datos. Aislamiento por UID de Firebase Auth
🇨🇴
Cumplimiento con Ley 1581 de 2012 — Protección de Datos Personales de Colombia
03 — Plan de Trabajo

Desarrollo del MVP

4 semanas · Metodología Scrum · Sprints de 1 semana · Daily standup 15 min vía Slack/WhatsApp

Sprint 1 · Semana 4
🏗 Fundación y Autenticación
  • Configurar React Native + Expo + Firebase (Auth, Firestore, Functions)
  • Autenticación por número de celular (OTP SMS)
  • Navegación base: 4 tabs inferiores
  • Pantalla de Onboarding de 3 pasos con animaciones
  • WatermelonDB para persistencia local con esquema de BD
  • Pipeline CI/CD con GitHub Actions + Expo EAS
🎯 Definición de HechoEl tendero puede registrarse con su celular y entrar a la app con código SMS.
Sprint 2 · Semana 5
📦 Inventario + Escáner
  • Pantalla de listado de productos con búsqueda en tiempo real
  • Formulario para agregar/editar producto (foto, precios, cantidad)
  • React Native Vision Camera + ML Kit para código de barras
  • Sincronización bidireccional WatermelonDB ↔ Firestore
  • Indicador visual de estado de sincronización en header
  • Casos de prueba para flujo offline
🎯 Definición de HechoEl tendero puede agregar un producto escaneando su código de barras, sin internet.
Sprint 3 · Semana 6
💰 Ventas + Alertas + Reportes
  • Módulo de registro rápido de ventas: producto → cantidad → confirmar
  • Descuento automático de inventario al registrar venta
  • Firebase Cloud Function: trigger de alerta cuando stock < mínimo
  • Pantalla de alertas con lista en rojo/amarillo
  • Reporte de cierre diario: ventas totales, top 5 productos
  • Gráfico de barras para ventas de los últimos 7 días
🎯 Definición de HechoEl tendero puede vender, recibir alerta de stock bajo y ver cuánto vendió hoy.
Sprint 4 · Semana 7
✨ Pulido + Exportación
  • Exportar inventario a Excel y reporte diario a PDF/imagen
  • Módulo de roles: cuenta de empleado con permisos limitados
  • Pruebas de usabilidad con 5 usuarios reales
  • Corrección de bugs críticos y friction points
  • Hardening de seguridad: reglas de Firestore y Functions
  • Video tutorial de 2 minutos + guía impresa QR
🎯 Definición de HechoLa app está lista para ser instalada en los teléfonos de los tenderos piloto.
Fase 3 — Validación

Piloto en Tienda Real

3 semanas · 3–5 tiendas en Bogotá · Meta: Validar retención, usabilidad y valor percibido

Semana 8
🏪 Instalación y Arranque
  • Seleccionar 3–5 tiendas piloto en Bogotá
  • Visita presencial de instalación y onboarding
  • Cargar inventario inicial junto al tendero
  • Check-in diario por WhatsApp los primeros 3 días
  • 100% de tenderos con inventario cargado al día 3
  • 0 desinstalaciones en semana 1
Semana 9
👀 Observación Activa
  • Monitorear uso diario vía Firebase Analytics
  • Entrevista de 15 min a mitad de semana
  • Registrar bugs y quejas en Notion
  • Hotfix deploy si hay bugs críticos
  • > 4 sesiones de uso por semana por tienda
  • NPS > 6 en entrevista intermedia
  • < 3 bugs críticos sin resolver
Semana 10
📋 Evaluación y Decisión
  • Entrevista de cierre con cada tendero piloto
  • Encuesta NPS + valoración de cada módulo
  • Análisis de datos de uso en Firebase
  • Informe final: ir / no ir a lanzamiento público
  • NPS > 7 en encuesta de cierre
  • > 60% de tenderos declara que pagaría
  • Retención: > 3 de 5 tiendas activas al día 21
Criterios para el Lanzamiento Público

5 Checkpoints de Go/No-Go

✅
Retención a 21 días > 60% en tiendas piloto
✅
NPS promedio ≥ 7/10
✅

✅
Tiempo de aprendizaje < 30 min desde instalación hasta primera venta
✅
Cero pérdidas de datos documentadas durante el piloto
